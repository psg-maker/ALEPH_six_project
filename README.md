# ALEPH — 내 계획과 실제를 담는 앱

FastAPI · SQLAlchemy로 만든 Plan → Do → See 기록 앱입니다. Vercel에서 화면과 API를 제공하고 Neon PostgreSQL에 배포 데이터를 저장합니다. 로컬 개발 기본 DB는 SQLite입니다. 로그인 없이 링크를 아는 사람이 자료를 조회·변경·삭제할 수 있습니다.

- 결과물: https://aleph-six-project.vercel.app/
- 소스: https://github.com/psg-maker/ALEPH_six_project
- 제출 판정과 남은 확인: [제출 점검표](SUBMISSION_CHECKLIST.md)
- 테이블·관계·날짜·삭제 규칙: [DB 계약](contracts/pds-schema-v2.json)
- 작업 과정과 검증 근거: [작업 기록](WORK_LOG.md)

## 제출용 확인 방법 — 4줄

1. 어디로: 공개 앱을 열고 `돌아보기`에서 `python 기초 코드 작성` 계획을 선택합니다.
2. 행동(3단계): 예정일 범위를 입력하고 `기간 적용` → 집계 카드 선택 → 해당 할 일의 `실행 기록 보기`를 누릅니다.
3. 통과 모습: 집계와 근거 목록이 같은 범위를 가리키고 실제 시간은 실행 기록의 합계와 일치합니다. 2026-10-23 사용자 검증 시 전체 5개·예상 330분·실제 70분(30+30+0+10)이었으며, 공개 자료는 이후 변경될 수 있습니다.
4. 안 될 때: 잘못된 날짜 범위는 안내 후 기존 범위를 유지합니다. 조회 오류는 재시도·집계 새로고침을 사용하고, 배포 오류는 Vercel 로그와 DB 연결 설정을 확인합니다.

## AI와 내 판단 — 제출용 초안 3줄

1. AI에 맡긴 일: 화면·API 구현 보조, 자동 테스트와 오류 분석, 문서 정리 및 점검 항목 도출.
2. 내가 직접 판단한 일: 실제 계획·할 일·실행 내용을 작성하고, 예상 시간을 70분·80분으로 수정했으며, Vercel에서 기간 필터·체크 해제·집계·새로고침 후 저장 유지를 직접 확인.
3. AI 판단을 그대로 확정하지 않은 일과 이유: AI의 “거의 완료”라는 안내만으로 제출하지 않고 원문 체크리스트와 최종 소스를 다시 점검하도록 요청함. 기능 확인과 전체 요건 충족은 구분해야 하기 때문.

위 3줄은 대화에서 확인한 사실에 근거한 초안입니다. 제출자는 실제 작업 과정과 일치하는지 최종 확인해야 합니다. 가이드라인의 C21~22 해석과 현재 완료 API의 차이는 점검표에 미해결로 남겨 두었습니다.

## 실행 — Windows Git Bash

현재 개발 환경은 Python 3.13입니다. 프로젝트 루트에서 실행합니다.

```bash
python -m venv venv
./venv/Scripts/python.exe -m pip install -r requirements.txt
./venv/Scripts/python.exe -m uvicorn app.main:app --reload
```

- 앱: http://127.0.0.1:8000/
- API: http://127.0.0.1:8000/docs
- 종료: `Ctrl+C`

가상환경이 있으면 생성 명령은 생략합니다. 포트 충돌 시 `--port 8001`을 사용하고 접속 주소도 바꿉니다. HTML 파일을 직접 열거나 Live Server로 실행하지 않습니다. Linux에서는 별도로 만든 가상환경의 `./venv/bin/python`을 사용합니다.

## 사용

1. 계획과 연결된 할 일을 작성합니다. 계획 수정 전 내용은 `수정 이력`에서 확인합니다.
2. 할 일의 `기록`에서 실제 시간을 분 단위로 입력합니다. 완료 체크와 실행 기록 저장은 별개이며, 예상 시간 수정도 실제 시간을 변경하지 않습니다.
3. `돌아보기`에서 계획과 기간을 선택하고 집계 숫자로 근거를 확인합니다. 회고의 개선점은 다음 계획의 설명에 반영할 수 있습니다.

기간 필터는 **할 일의 예정일**을 기준으로 시작·종료일을 모두 포함합니다. 마감일이나 계획 종료일을 변경하지 않습니다. 날짜 한쪽만 입력할 수 있고, `전체 기간`으로 제한을 해제합니다. `기간 적용` 전의 입력은 현재 집계를 바꾸지 않습니다.

대상 할 일에 연결된 모든 실행 기록을 실행 날짜와 무관하게 포함합니다. 완료는 현재 상태, 지연은 서울 기준 오늘로 계산하며 과거 상태를 복원하지 않습니다. API의 `GET /tasks`, `GET /plans/{plan_id}/summary`, `GET /plans/{plan_id}/executions`는 선택 쿼리 `start_date`·`end_date`(YYYY-MM-DD)를 공유하며 잘못된 날짜나 역전 범위는 422입니다.

반복 완료는 현재 `completed_at`을 유지하고 Execution을 자동 생성하지 않습니다. 체크 해제는 완료 시각을 비우며 기존 실행 기록은 유지합니다. 이 구현과 C21~22의 “완료 기록 1건” 요건 사이의 차이는 최종 확인 대상입니다.

## 데이터 보관과 배포

| 환경 | DB | 선택 |
| --- | --- | --- |
| 로컬 기본값 | SQLite | 환경변수 미설정 시 현재 폴더의 `planner.db` |
| Vercel 배포 | Neon PostgreSQL | 환경변수 `DATABASE_URL` |

로컬과 배포 DB는 별개이며 자동 동기화되지 않습니다. 로컬에서 배포 DB 주소를 설정하면 공개 앱 자료를 변경하게 됩니다. 소스만 clone하면 개인 DB가 복원되지는 않습니다.

Vercel의 `DATABASE_URL`은 설치 드라이버에 맞춰 `postgresql+psycopg2://`로 설정하고 Neon의 SSL 옵션을 유지합니다. 실제 주소·비밀번호는 소스나 Git에 넣지 않습니다. 환경변수 변경 후 재배포합니다. Vercel이 `app/main.py`를 실행하며 GitHub Pages는 이 Python 앱의 실행 환경이 아닙니다.

SQLite → Neon의 7개 테이블 이전은 완료했습니다. [이전 스크립트](scripts/migrate_to_neon.py)의 `NEON_DATABASE_URL`은 앱 환경변수와 다르며, 완료된 이전을 다시 실행하지 않습니다.

로컬 DB 백업은 서버를 종료한 뒤 별도 위치에 보관합니다. `전체 기록 내보내기`는 현재 연결 DB의 7개 테이블을 `planner-export.json`으로 다운로드하며 가져오기 API는 없습니다. 새 DB의 테이블은 시작 시 생성하지만 기존 DB 컬럼은 자동 변경하지 않습니다. 오래된 SQLite에서 `executions.blocked_reason`이 없으면 백업 후 컬럼을 확인하고 필요한 경우에만 `ALTER TABLE executions ADD COLUMN blocked_reason TEXT`를 적용합니다.

DB 계약은 명세 문서이며 마이그레이션을 실행하지 않습니다. 이번 점검은 현재 ORM 모델과의 대조이며 실제 Neon 카탈로그 전체를 재검사한 것은 아닙니다.

## 날짜와 시간

`app/time_utils.py`의 `today_in_seoul()`·`now_in_seoul()`은 서버 지역과 관계없이 UTC+9를 사용합니다. 자동 생성·수정·완료 시각은 기존 DB 형식에 맞춰 시간대 표시 없이 저장합니다. 기존 값과 사용자가 입력한 실행 시작·종료 시각은 일괄 변환하지 않습니다.

지연은 미완료이고 마감일이 서울 기준 오늘보다 이전인 할 일입니다. 오늘 마감·완료·마감 미입력은 제외합니다. 실제 시간은 수동 입력값이며 시작·종료 시각의 차이로 자동 계산하지 않습니다.


DOM/API 검증은 [테스트 설명](tests/README.md)을 따릅니다. 메모리 DB·임시 DB 테스트는 개인 DB와 분리되며 실제 모바일 배치나 배포 환경의 모든 동작을 대신하지 않습니다.

2026-10-23 사용자 배포 확인: 기간 경계·빈 기간·전체 기간·역전 날짜 안내·계획 전환·완료 해제·예상 330분·실제 70분 및 근거 일치·새로고침 후 기록 유지. 이 확인을 전체 요건 준수 판정으로 확대하지 않습니다.

## 휴대폰

배포 앱은 공개 주소로 접속합니다. 로컬 확인 시 PC와 휴대폰을 같은 Wi-Fi에 연결하고 서버를 실행합니다.

```bash
./venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`ipconfig`의 PC IPv4로 `http://PC주소:8000/`에 접속합니다. 신뢰하는 사설 네트워크에서만 방화벽을 허용하고 확인 후 종료합니다. 이 주소는 제출용 공개 주소가 아닙니다.

채팅 버전의 빈 제목 자동 생성, 계획 완료/보관/삭제는 현재 제공하는 기능이 아닙니다.
